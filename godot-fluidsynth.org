* Godot FluidSynth
This plugin exposes [[https://www.fluidsynth.org/][FluidSynth]] to Godot 4 via [[https://docs.godotengine.org/en/stable/tutorials/scripting/gdextension/what_is_gdextension.html][GDExtension]] and the [[https://github.com/godotengine/godot-cpp][godot-cpp]] bindings. It exists for realtime MIDI playback inside the engine — complementing Godot's built-in MIDI input — by rendering SoundFont-driven synthesis directly into Godot's audio server.

** Usage
Build prerequisites and commands live in the [[file:README.md][README]] and in =SConstruct=. The example scene =project/main.tscn= drives the singleton from GDScript.

*** Playing a MIDI file
#+begin_src gdscript
extends Node2D
var fluidsynth: Node

func _ready() -> void:
	fluidsynth = Engine.get_singleton("FluidSynth")
	fluidsynth.call("play_midi")

# Direct voice control:
fluidsynth.call("program_select", 0, 0, 0)
fluidsynth.call("note_on", 0, 60, 127)
fluidsynth.call("pitch_bend", 0, 8192)
fluidsynth.call("note_off", 0, 60)
#+end_src

Imported assets are =MidiFileReader= (=.midstr=) and =SoundFontFileReader= (=.sf2str=) resources; paths resolve through =ResourceLoader= so exported games bundle them. Wiring in =project/main.gd:7= is late-bound via =call()= to avoid a hard GDScript dependency on the GDExtension.

** Design
FluidSynth assumes it owns file I/O and the audio driver. Godot owns both: assets are packed into =res://= and =.pck=, and the audio server pulls frames. The port bridges that gap with custom rendering, a custom SoundFont loader, and in-memory MIDI injection — three classes plus a GDScript importer.

- =FluidSynth= :: Singleton =Node= that owns =fluid_settings_t=, =fluid_synth_t= and a list of =fluid_player_t= handles, synthesizes into a float buffer, and is registered as =Engine singleton "FluidSynth"=.
- =AudioStreamFluidSynth= / =AudioStreamPlaybackFluidSynth= :: =AudioStream= pair that delegates =gen_tone= to the singleton, so the stream can be used in an =AudioStreamPlayer= (see =project/main.tscn:7=).
- =MidiFileReader= / =SoundFontFileReader= :: =Resource= wrappers holding raw =PackedByteArray= bytes so =.mid= / =.sf2= travel through Godot's resource system.
- =project/addons/midi/= :: =EditorImportPlugin= + =ResourceFormatLoader/Saver= converting =.mid→.midstr= and =.sf2→.sf2str= at import time.

*** Loading SoundFonts at runtime
The singleton's constructor registers a custom sfloader before any font is touched; the loader claims pseudo-paths beginning with =&= and decodes them back into memory pointers.

=SoundFontFileReader= implements the =fluid_sfloader_t= callbacks over its =PackedByteArray= (=src/soundfont_file_reader.cpp:82=); =sf_open= accepts only =&%p=, decodes the pointer, and returns it as the handle.

#+begin_src cpp :tangle src/soundfont_file_reader.cpp
void *SoundFontFileReader::sf_open(const char *filename) {
	void *p;
	if (filename[0] != '&')
		return NULL;
	sscanf(filename, "&%p", &p);
	Ref<SoundFontFileReader> *reader = reinterpret_cast<Ref<SoundFontFileReader> *>(const_cast<void *>(p));
	(*reader)->open();
	return p;
}
#+end_src

*** Handing MIDI data to the synthesizer
MIDI reaches the synth in-memory via =fluid_player_add_mem=. =FluidSynth::play_midi= (=src/fluidsynth_gdextension.cpp:99=) copies the =MidiFileReader= bytes into a stack buffer and feeds a fresh =fluid_player_t=:

#+begin_src cpp :tangle src/fluidsynth_gdextension.cpp
void FluidSynth::play_midi(Ref<MidiFileReader> p_midi_file) {
	Ref<MidiFileReader> local_midi_file;
	if (p_midi_file != NULL) {
		if (ResourceLoader::get_singleton()->exists(p_midi_file->get_path())) {
			Variant resource = ResourceLoader::get_singleton()->load(p_midi_file->get_path());
			local_midi_file = resource;
		}
	} else {
		local_midi_file = midi_file;
	}
	if (local_midi_file != NULL) {
		PackedByteArray byte_array = local_midi_file->get_data();
		if (byte_array.size() > 0) {
			fluid_player_t *fluid_player = new_fluid_player(synth);
			char midi_file[byte_array.size()];
			for (int i = 0; i < byte_array.size(); i++)
				midi_file[i] = byte_array[i];
			fluid_player_add_mem(fluid_player, midi_file, byte_array.size());
			fluid_player_play(fluid_player);
			fluid_players.append(fluid_player);
		}
	}
}
#+end_src

*** Rendering pipeline
=AudioStreamFluidSynth::gen_tone= delegates to the singleton, which renders interleaved stereo floats and fans them into Godot =AudioFrame=s:

#+begin_src cpp :tangle src/fluidsynth_gdextension.cpp
int FluidSynth::gen_tone(AudioFrame *p_buffer, float p_rate, int p_frames) {
	int64_t to_fill = p_frames;
	if (to_fill > 44100) to_fill = 44100;
	int result = fluid_synth_write_float(synth, to_fill, buffer, 0, 2, buffer, 1, 2);
	if (result == FLUID_FAILED) UtilityFunctions::print("failed to write to fluid_synth");
	int index = 0, p_index = 0;
	while (to_fill > 0) {
		p_buffer[p_index].left = buffer[index];
		p_buffer[p_index].right = buffer[index + 1];
		index += 2; p_index += 1; to_fill -= 1;
	}
	return p_frames;
}
#+end_src

=AudioStreamPlaybackFluidSynth::_mix= pulls whatever frames are available from the playback; =FluidSynth::process= (=src/fluidsynth_gdextension.cpp:142=) drains finished players each =NOTIFICATION_INTERNAL_PROCESS=:

#+begin_src cpp :tangle src/fluidsynth_gdextension.cpp
void FluidSynth::process(double delta) {
	Vector<fluid_player_t *> to_remove;
	for (int i = 0; i < fluid_players.size(); ++i)
		if (fluid_player_get_status(fluid_players[i]) == FLUID_PLAYER_DONE)
			to_remove.append(fluid_players[i]);
	for (int i = 0; i < to_remove.size(); ++i) {
		delete_fluid_player(to_remove[i]);
		fluid_players.erase(to_remove[i]);
	}
}
#+end_src

** Class architecture
The library transliterates Godot's audio subsystem onto FluidSynth: =AudioStream= is a sound source hosted by =AudioStreamPlayer=, =InputEventMIDI= carries live input, and =AudioServer= mixes. FluidSynth's pieces land on the same seams — =fluid_synth_t= renders, =fluid_player_t= feeds it MIDI files, =fluid_sequencer_t= routes live events in — and they are exposed as two =AudioStream= subclasses rather than nodes, so they drop straight into Godot's audio graph. Every FluidSynth callback is marshalled onto a Godot signal, the way the [[https://github.com/arlez80/godot-midi-player-g4][godot-midi-player]] addon does.

Each stream owns its own =fluid_synth_t= built from the shared =fluid_settings_t= held by the =FluidSynth= singleton; the singleton is settings, nothing more. Sharing one synth between streams — e.g. an SMF stream and a sequencer stream driving the same instrument — is a caller's choice: pass them the same underlying =fluid_synth_t= and FluidSynth mixes whatever events arrive. The current monolith — one node owning settings, synth, players and the pump — dissolves into this.

*** FluidSynth — the settings singleton
The engine singleton =Engine.get_singleton("FluidSynth")= owns =fluid_settings_t= — the shared settings every stream's synth is built from (audio buffer size, sample rate, polyphony defaults, …). Its surface is the runtime settings keys; it is the single place global tuning lives. The convenience surface the monolith carried (=play_midi=, =note_on/off=, =set_soundfont=, …) is transitional: the streams take it over, and the facade is removed once scenes migrate.

*** AudioStreamFluidSynthSMF — MIDI file playback
An =AudioStream= that plays Standard MIDI Files: it owns a =fluid_synth_t= (from the shared settings), the =fluid_player_t=, and the soundfont. Dropping it into an =AudioStreamPlayer= is all the wiring the SMF path needs — the play lifecycle maps onto Godot's audio API instead of bespoke methods:
- =AudioStream._instantiate_playback()= → =AudioStreamFluidSynthSMFPlayback=
- playback =_mix= renders the synth (no =gen_tone=); =_start= begins the =fluid_player_t=; =_stop= stops it; =_seek= forwards to =fluid_player_seek=
- =_get_length()= → =total_ticks= / ticks-per-second; =_get_stream_name()= → the MIDI file name

Properties and transport, drawn from the [[https://www.fluidsynth.org/wiki/api/midi-player/][MIDI File Player API]]:
- Properties :: =midi_file= (=Ref<MidiFileReader>=), =soundfont= (path or =SoundFontFileReader=), =gain=, =polyphony=, =loop=
- Transport :: =tick= (=fluid_player_get_current_tick=), =total_ticks= (=fluid_player_get_total_ticks=), =bpm= (=fluid_player_get_bpm=), =division= (PPQ, =fluid_player_get_division=), =tempo= (=fluid_player_set_tempo=; =tempo_type= =FLUID_PLAYER_TEMPO_INTERNAL=, =FLUID_PLAYER_TEMPO_EXTERNAL_BPM= or =FLUID_PLAYER_TEMPO_EXTERNAL_MIDI=)

#+begin_src gdscript :tangle no
var stream := AudioStreamFluidSynthSMF.new()
stream.midi_file = load("res://song.mid")
stream.soundfont = "res://FluidR3_GM.sf2"
stream.loop = 2
$AudioStreamPlayer.stream = stream
$AudioStreamPlayer.play()
await stream.finished
print("played %d ticks" % stream.total_ticks)
#+end_src

The stream is also the event surface. Two FluidSynth callbacks carry the whole stream — =fluid_player_set_playback_callback= (a =handle_midi_event_func_t= invoked for every MIDI message) and =fluid_player_set_tick_callback= (=handle_midi_tick_func_t=) — and every one of them is forwarded onto a Godot signal. The reference implementation for this surface is the [[https://github.com/arlez80/godot-midi-player-g4][godot-midi-player]] addon (=project/addons/godot-midi-player=): pure GDScript and slower, but it emits *more* of the SMF content than FluidSynth exposes, and its =MidiPlayer.gd:301= signal block is the contract our signals mirror. The two players stay interchangeable in the unit tests, where the addon acts as the oracle.

Playback signals (from =handle_midi_event_func_t=):
- =note_on(channel, key, velocity)=, =note_off(channel, key)=
- =control_change(channel, controller, value)=, =program_change(channel, program)=
- =pitch_bend(channel, value)= (0-16383, 8192 center), =key_pressure(channel, key, value)=, =channel_pressure(channel, value)=
- =midi_event(channel, event: Dictionary)= — the raw event (type + fields) for consumers that want everything =fluid_midi_event_t= can carry (sysex, meta)

Transport signals:
- =ticked(tick)= from =handle_midi_tick_func_t= (fired at PPQ × BPM per minute)
- =finished= when status flips to =FLUID_PLAYER_DONE=; =looped= on playlist wrap
- =tempo_changed(bpm)= on the set-tempo meta event

SMF meta-text signals (decoded from text/lyrics-bearing events in the stream, as the addon does at =MidiPlayer.gd:1007=):
- =midi_text(text)=, =midi_lyrics(text)=, =midi_copyright(text)=
- =midi_track_name(channel, name)=, =midi_instrument_name(channel, name)=
- =midi_marker(marker)=, =midi_cue_point(cue)=
- =gm_system_on=, =gs_reset=, =xg_system_on= — decoded from the sys-ex stream exactly as =MidiPlayer._process_track_sys_ex= does (=MidiPlayer.gd:1040=)

*** AudioStreamFluidSynthSequencer — live voice control
An =AudioStream= for live performance: it owns a =fluid_synth_t= (from the shared settings), the =fluid_sequencer_t=, and the soundfont. Host it in an =AudioStreamPlayer= so the synth renders, then drive it with the voice-control proxy — each method forwards to the matching =fluid_synth_*= call on its own synth, or queues through the sequencer:
- Controls (immediate channel messages) :: =note_on/off=, =cc=, =pitch_bend=, =program_change=, =program_select=, =bank_select=, =sfont_select=, =key_pressure=, =channel_pressure=, =all_notes_off=, =all_sounds_off=, =system_reset=, =sysex=
- State queries :: =get_cc=, =get_pitch_bend=, =get_pitch_wheel_sens=, =get_program=, =get_gen= / =set_gen= (NRPN generator offset), =voice_count=
- Scheduled delivery :: =fluid_sequencer_send_now= / =fluid_sequencer_send_at= (absolute or relative ticks) for the note/channel builders above; =fluid_sequencer_remove_events= cancels
- Live input :: =receive_raw_midi_message(event: InputEventMIDI)=, mirroring =MidiPlayer.receive_raw_midi_message= (=MidiPlayer.gd:729=), wraps the incoming event and hands it to =fluid_sequencer_add_midi_event_to_buffer=
- Clock :: sequencer-native milliseconds by default; =fluid_sequencer_set_time_scale= (or a =FLUID_SEQ_SCALE= event) retunes it

#+begin_src gdscript :tangle no
var seq := AudioStreamFluidSynthSequencer.new()
seq.soundfont = "res://FluidR3_GM.sf2"
$AudioStreamPlayer.stream = seq
$AudioStreamPlayer.play()
seq.note_on(0, 60, 90)     # immediate, via the sequencer queue
#+end_src

Rendering runs through the playback =_mix= (=_instantiate_playback= → =AudioStreamFluidSynthSequencerPlayback=), the same tight fit as the SMF stream. Signals:
- =event_received(event: Dictionary)= — a destination client's =fluid_event_callback_t= firing (client id, type, channel + fields)
- =timer_event(data)=, =client_registered(id, name)=, =client_unregistered(id)=
- =tick(tick)=, =time_scale(scale)= — the sequencer clock when not advanced by the synth

*** MidiFileReader and SoundFontFileReader
Both are =Resource= subclasses holding =PackedByteArray data= (=src/midi_file_reader.h:11=, =src/soundfont_file_reader.h:13=). The SoundFont reader additionally implements the random-access =open/read/seek/tell= surface used by the sfloader callbacks and advertises extensions =midstr= / =sf2str= for the importer.

** Delivery plan
Signal plumbing must exist before anything event-shaped consumes it, so the phases order dependencies first; each lands as its own PR.

1. *Stream refactor* — split the monolith into =AudioStreamFluidSynthSMF= + =AudioStreamFluidSynthSequencer= (each owning a =fluid_synth_t= built from the shared settings); move =fluid_player_t= into the SMF stream and =fluid_sequencer_t= into the sequencer stream; replace =gen_tone= with the playback =_mix= virtuals; retire =AudioStreamMyTone= and the old =AudioStreamFluidSynth= shim; keep the =FluidSynth= singleton as settings + a transitional facade. Existing tests pass through the facade.
2. *Transport & performance surface* — the SMF stream's transport + properties, validation guards (=fluid_is_midifile=); unit tests mirroring the existing suites.
3. *Deferred-emission infrastructure* — a lock-free queue fed from FluidSynth threads, drained and emitted during the playback's =_process=; every signal reuses it. Then: playback callback → the granular channel + meta signals above, tick callback → =ticked=, status → =finished= / =looped=; migrate the =_process= watchdog onto =finished=; integration tests await signals instead of frame-counting.
4. *Channel voice completeness* — the full =midi-messages= controls on the sequencer stream (bank/sfont/program select, key/channel pressure, sysex) plus the =get_*= queries.
5. *FX & settings surface* — reverb/chorus groups and settings keys on the streams and singleton.
6. *Sequencer scheduling* — the =send_at= / time-scale / cancellation surface.
7. *Voice callbacks* — the attach sweep and its two deferred signals.

The =godot-midi-player= addon (=project/addons/godot-midi-player=, fetched via =make addons=) rides along in the integration suites: it is the behavioral oracle for the signal contract, and =AudioStreamFluidSynthSMF= is expected to be signal-compatible with it (both fed the same =project/assets/*.mid= fixtures).
