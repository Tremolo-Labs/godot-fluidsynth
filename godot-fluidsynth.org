* Godot FluidSynth
This plugin exposes [[https://www.fluidsynth.org/][FluidSynth]] to Godot 4 via [[https://docs.godotengine.org/en/stable/tutorials/scripting/gdextension/what_is_gdextension.html][GDExtension]] and the [[https://github.com/godotengine/godot-cpp][godot-cpp]] bindings. It exists for realtime MIDI playback inside the engine — complementing Godot's built-in MIDI input — by rendering SoundFont-driven synthesis directly into Godot's audio server.

** Usage
Build prerequisites and commands live in the [[file:README.md][README]] and in =SConstruct=. The example scene =project/main.tscn= drives the singleton from GDScript.

*** Playing a MIDI file
#+begin_src gdscript
extends Node2D
var fluidsynth: Node

func _ready() -> void:
	fluidsynth = Engine.get_singleton("FluidSynth")
	fluidsynth.call("play_midi")

# Direct voice control:
fluidsynth.call("program_select", 0, 0, 0)
fluidsynth.call("note_on", 0, 60, 127)
fluidsynth.call("pitch_bend", 0, 8192)
fluidsynth.call("note_off", 0, 60)
#+end_src

Imported assets are =MidiFileReader= (=.midstr=) and =SoundFontFileReader= (=.sf2str=) resources; paths resolve through =ResourceLoader= so exported games bundle them. Wiring in =project/main.gd:7= is late-bound via =call()= to avoid a hard GDScript dependency on the GDExtension.

** Design
FluidSynth assumes it owns file I/O and the audio driver. Godot owns both: assets are packed into =res://= and =.pck=, and the audio server pulls frames. The port bridges that gap with custom rendering, a custom SoundFont loader, and in-memory MIDI injection — three classes plus a GDScript importer.

- =FluidSynth= :: Singleton =Node= that owns =fluid_settings_t=, =fluid_synth_t= and a list of =fluid_player_t= handles, synthesizes into a float buffer, and is registered as =Engine singleton "FluidSynth"=.
- =AudioStreamFluidSynth= / =AudioStreamPlaybackFluidSynth= :: =AudioStream= pair that delegates =gen_tone= to the singleton, so the stream can be used in an =AudioStreamPlayer= (see =project/main.tscn:7=).
- =MidiFileReader= / =SoundFontFileReader= :: =Resource= wrappers holding raw =PackedByteArray= bytes so =.mid= / =.sf2= travel through Godot's resource system.
- =project/addons/midi/= :: =EditorImportPlugin= + =ResourceFormatLoader/Saver= converting =.mid→.midstr= and =.sf2→.sf2str= at import time.

*** Loading SoundFonts at runtime
The singleton's constructor registers a custom sfloader before any font is touched; the loader claims pseudo-paths beginning with =&= and decodes them back into memory pointers.

#+begin_src cpp :tangle src/soundfont_file_reader.cpp
void *SoundFontFileReader::sf_open(const char *filename) {
	void *p;
	if (filename[0] != '&')
		return NULL;
	sscanf(filename, "&%p", &p);
	Ref<SoundFontFileReader> *reader = reinterpret_cast<Ref<SoundFontFileReader> *>(const_cast<void *>(p));
	(*reader)->open();
	return p;
}

*** Handing MIDI data to the synthesizer
MIDI reaches the synth in-memory via =fluid_player_add_mem=. =FluidSynth::play_midi= (=src/fluidsynth_gdextension.cpp:99=) copies the =MidiFileReader= bytes into a stack buffer and feeds a fresh =fluid_player_t=:

#+begin_src cpp :tangle src/fluidsynth_gdextension.cpp
void FluidSynth::play_midi(Ref<MidiFileReader> p_midi_file) {
	Ref<MidiFileReader> local_midi_file;
	if (p_midi_file != NULL) {
		if (ResourceLoader::get_singleton()->exists(p_midi_file->get_path())) {
			Variant resource = ResourceLoader::get_singleton()->load(p_midi_file->get_path());
			local_midi_file = resource;
		}
	} else {
		local_midi_file = midi_file;
	}
	if (local_midi_file != NULL) {
		PackedByteArray byte_array = local_midi_file->get_data();
		if (byte_array.size() > 0) {
			fluid_player_t *fluid_player = new_fluid_player(synth);
			char midi_file[byte_array.size()];
			for (int i = 0; i < byte_array.size(); i++)
				midi_file[i] = byte_array[i];
			fluid_player_add_mem(fluid_player, midi_file, byte_array.size());
			fluid_player_play(fluid_player);
			fluid_players.append(fluid_player);
		}
	}
}
#+end_src

*** Rendering pipeline
=AudioStreamFluidSynth::gen_tone= delegates to the singleton, which renders interleaved stereo floats and fans them into Godot =AudioFrame=s:

#+begin_src cpp :tangle src/fluidsynth_gdextension.cpp
int FluidSynth::gen_tone(AudioFrame *p_buffer, float p_rate, int p_frames) {
	int64_t to_fill = p_frames;
	if (to_fill > 44100) to_fill = 44100;
	int result = fluid_synth_write_float(synth, to_fill, buffer, 0, 2, buffer, 1, 2);
	if (result == FLUID_FAILED) UtilityFunctions::print("failed to write to fluid_synth");
	int index = 0, p_index = 0;
	while (to_fill > 0) {
		p_buffer[p_index].left = buffer[index];
		p_buffer[p_index].right = buffer[index + 1];
		index += 2; p_index += 1; to_fill -= 1;
	}
	return p_frames;
}
#+end_src

=AudioStreamPlaybackFluidSynth::_mix= pulls whatever frames are available from the playback; =FluidSynth::process= (=src/fluidsynth_gdextension.cpp:142=) drains finished players each =NOTIFICATION_INTERNAL_PROCESS=:

#+begin_src cpp :tangle src/fluidsynth_gdextension.cpp
void FluidSynth::process(double delta) {
	Vector<fluid_player_t *> to_remove;
	for (int i = 0; i < fluid_players.size(); ++i)
		if (fluid_player_get_status(fluid_players[i]) == FLUID_PLAYER_DONE)
			to_remove.append(fluid_players[i]);
	for (int i = 0; i < to_remove.size(); ++i) {
		delete_fluid_player(to_remove[i]);
		fluid_players.erase(to_remove[i]);
	}
}
#+end_src

** Class architecture
The library transliterates Godot's audio subsystem onto FluidSynth: =AudioStream= is the sound source, =AudioStreamPlayer= hosts it, =InputEventMIDI= carries live input, and =AudioServer= mixes. FluidSynth's pieces land on the same seams — =fluid_synth_t= is the source, =fluid_player_t= feeds it MIDI files, =fluid_sequencer_t= routes live events in, and =fluid_synth_write_float= delivers frames to Godot's mixer.

Today one =FluidSynth= singleton is a monolith holding settings, synth, players and the pump. The refactor splits it along those seams: =AudioStreamFluidSynth= *is* the synthesizer and owns the controls, =FluidSynthPlayer= plays MIDI into a synth, =FluidSynthSequencer= adapts live input, and the singleton shrinks to the default-synth facade. Every FluidSynth callback is marshalled onto a Godot signal, so GDScript sees the event stream the way the [[https://github.com/arlez80/godot-midi-player-g4][godot-midi-player]] addon does.

*** AudioStreamFluidSynth — the synthesizer
Owns =fluid_synth_t= and =fluid_settings_t= plus the soundfont, and renders through =gen_tone= (=_instantiate_playback= → =AudioStreamPlaybackFluidSynth=) into Godot =AudioFrame=s. The synth is the *instrument*: all voice control is a proxy — each method forwards to the matching =fluid_synth_*= call on its own synth.

#+begin_src gdscript :tangle no
var synth := AudioStreamFluidSynth.new()
synth.soundfont = "res://FluidR3_GM.sf2"
$AudioStreamPlayer.stream = synth
synth.note_on(0, 60, 90)
#+end_src

- Controls (immediate channel messages) :: =note_on/off=, =cc=, =pitch_bend=, =program_change=, =program_select=, =bank_select=, =sfont_select=, =key_pressure=, =channel_pressure=, =all_notes_off=, =all_sounds_off=, =system_reset=, =sysex=
- State queries :: =get_cc=, =get_pitch_bend=, =get_pitch_wheel_sens=, =get_program=, =get_gen= / =set_gen= (NRPN generator offset), =voice_count=
- Properties :: =soundfont= (path or =SoundFontFileReader=), =gain=, =polyphony=, =midi_channels=
- FX groups :: reverb (enabled/room-size/damping/width/level) and chorus (enabled/count/level/speed/depth) routed through =synth.reverb.*= / =synth.chorus.*= settings keys — never the deprecated direct setters; per-channel sends land via cc 91/93
- Settings :: every runtime-relevant key becomes a property (dynamic sample loading, midi channels, cpu cores, period config); shell settings and LADSPA stay out — buses already bridge effects, and LADSPA is Linux-only
- Validation :: =fluid_is_soundfont= / =fluid_is_midifile= guards before loads

Voice callbacks ship deliberately, sharp edges documented: after each played or scheduled note-on, unregistered voices from =fluid_synth_get_voicelist= receive =fluid_voice_set_callback=; events flow through the deferred queue as =voice_note_off(id)= / =voice_finished(id)=. Class docs carry the header warnings verbatim: callbacks fire from the synthesis thread, block the DSP loop while running, must not call public API, and NOTEOFF never fires for one-shot percussion samples.

*** FluidSynth — default-synth facade (singleton)
The engine singleton =Engine.get_singleton("FluidSynth")= owns the *default* =AudioStreamFluidSynth= and the render pump that reaps finished players. Its old surface — =set_soundfont=, =play_midi=, =note_on/off=, =pitch_bend=, =program_select=, =soundfont/midi_file= — is retained as a convenience facade forwarding to the default synth and player, so existing scenes and the test suites keep working. New code should target an explicit =AudioStreamFluidSynth=; the facade exists for scenes that want one synth without wiring.

*** FluidSynthPlayer
Plays tracks: transport over Standard MIDI Files. Wraps one =fluid_player_t= targeted at a synth — an =AudioStreamFluidSynth=, defaulting to the =FluidSynth= singleton's default — and replaces the =_process=-watchdog polling that currently recycles the player (and races replays into duplicated playlists) with an event-driven lifecycle. It is the =AudioStreamPlayer= analogue: it hosts the synth's stream in the mix while the player walks the SMF into it.

Transport and properties, drawn from the [[https://www.fluidsynth.org/wiki/api/midi-player/][MIDI File Player API]]:
- Transport :: =play=, =stop=, =seek(ticks)=, =set_loop(n)= (= -1 = loops forever), =join=
- Properties :: =tick= (=fluid_player_get_current_tick=), =total_ticks= (=fluid_player_get_total_ticks=), =bpm= (=fluid_player_get_bpm=), =division= (PPQ, =fluid_player_get_division=), =tempo= (set via =fluid_player_set_tempo= with a =tempo_type= of =FLUID_PLAYER_TEMPO_INTERNAL=, =FLUID_PLAYER_TEMPO_EXTERNAL_BPM= or =FLUID_PLAYER_TEMPO_EXTERNAL_MIDI=)

#+begin_src gdscript :tangle no
var synth := AudioStreamFluidSynth.new()
synth.soundfont = "res://FluidR3_GM.sf2"

var p := FluidSynthPlayer.new()
p.synth = synth             # the target AudioStreamFluidSynth
p.midi_file = load("res://song.mid")
add_child(p)                # hosts the stream in the mix + walks the SMF
p.set_loop(2)
p.play()
await p.finished
print("played %d ticks" % p.total_ticks)
#+end_src

The soundfont stays with the synth: =FluidSynthPlayer= plays against whatever font its target =AudioStreamFluidSynth= has loaded.

The player is also the event surface. Two FluidSynth callbacks carry the whole stream — =fluid_player_set_playback_callback= (a =handle_midi_event_func_t= invoked for every MIDI message) and =fluid_player_set_tick_callback= (=handle_midi_tick_func_t=) — and every one of them is forwarded onto a Godot signal. The reference implementation for this surface is the [[https://github.com/arlez80/godot-midi-player-g4][godot-midi-player]] addon (=project/addons/godot-midi-player=): pure GDScript and slower, but it emits *more* of the SMF content than FluidSynth exposes, and its =MidiPlayer.gd:301= signal block is the contract our signals mirror. The two players stay interchangeable in the unit tests, where the addon acts as the oracle.

Playback signals (from =handle_midi_event_func_t=):
- =note_on(channel, key, velocity)=, =note_off(channel, key)=
- =control_change(channel, controller, value)=, =program_change(channel, program)=
- =pitch_bend(channel, value)= (0-16383, 8192 center), =key_pressure(channel, key, value)=, =channel_pressure(channel, value)=
- =midi_event(channel, event: Dictionary)= — the raw event (type + fields) for consumers that want everything =fluid_midi_event_t= can carry (sysex, meta)

Transport signals:
- =ticked(tick)= from =handle_midi_tick_func_t= (fired at PPQ × BPM per minute)
- =finished= when status flips to =FLUID_PLAYER_DONE=; =looped= on playlist wrap
- =tempo_changed(bpm)= on the set-tempo meta event

SMF meta-text signals (decoded from text/lyrics-bearing events in the stream, as the addon does at =MidiPlayer.gd:1007=):
- =midi_text(text)=, =midi_lyrics(text)=, =midi_copyright(text)=
- =midi_track_name(channel, name)=, =midi_instrument_name(channel, name)=
- =midi_marker(marker)=, =midi_cue_point(cue)=
- =gm_system_on=, =gs_reset=, =xg_system_on= — decoded from the sys-ex stream exactly as =MidiPlayer._process_track_sys_ex= does (=MidiPlayer.gd:1040=)

*** FluidSynthSequencer
The live-input path into a synth: it adapts Godot's =InputEventMIDI= stream to an =AudioStreamFluidSynth= 's controls. The sequencer owns =fluid_sequencer_t= and registers its target synth as a destination client at construction (=fluid_sequencer_register_fluidsynth=). Its headline path is =fluid_sequencer_add_midi_event_to_buffer=, whose signature *is* a =handle_midi_event_func_t=: hand it a raw MIDI event (e.g. from Godot's =InputEventMIDI=, the same live path the reference's =receive_raw_midi_message= uses at =MidiPlayer.gd:729=) and it reaches the synth as soon as possible. This is the "strike a voice without loading a song" seam.

Scheduled delivery — each call builds a typed =fluid_event_*= and dispatches it through the queue with =fluid_sequencer_send_now= (immediate) or =fluid_sequencer_send_at= (absolute or relative ticks):
- Notes :: =note_on(channel, key, vel)=, =note_off(channel, key)=, =note(channel, key, vel, duration)=
- Channel :: =control_change=, =program_change=, =program_select(sfont_id, bank, preset)=, =pitch_bend=, =pitch_wheelsens=, =key_pressure=, =channel_pressure=, =sustain=, =modulation=, =pan=, =volume=, =reverb_send=, =chorus_send=, =all_notes_off=, =all_sounds_off=, =system_reset=
- Housekeeping :: =timer(data)=, =set_time_scale(scale)=, =unregistering=

Live input — =receive_raw_midi_message(event: InputEventMIDI)=, mirroring =MidiPlayer.receive_raw_midi_message= (=MidiPlayer.gd:729=), wraps the incoming event and hands it to =fluid_sequencer_add_midi_event_to_buffer=.

Cancellation and clock: =fluid_sequencer_remove_events= cancels queued sends; time is sequencer-native milliseconds by default; =fluid_sequencer_set_time_scale= (or a =FLUID_SEQ_SCALE= event) retunes it.

Signals:
- =event_received(event: Dictionary)= — a destination client's =fluid_event_callback_t= firing (client id, type, channel + fields)
- =timer_event(data)=, =client_registered(id, name)=, =client_unregistered(id)=
- =tick(tick)=, =time_scale(scale)= — the sequencer clock when not advanced by the synth

Both are =Resource= subclasses holding =PackedByteArray data= (=src/midi_file_reader.h:11=, =src/soundfont_file_reader.h:13=). ** Delivery plan
Signal plumbing must exist before anything event-shaped consumes it, so the phases order dependencies first; each lands as its own PR.

1. *Synth ownership* — move =fluid_synth_t= + settings + soundfont into =AudioStreamFluidSynth= and proxy the =fluid_synth_*= controls there; shrink =FluidSynth= to the default-synth facade forwarding its old surface. Existing tests keep passing through the facade.
2. *Transport & performance surface* — =FluidSynthPlayer= transport + properties, validation guards (=fluid_is_midifile=); unit tests mirroring the existing suites.
3. *Deferred-emission infrastructure* — a lock-free queue fed from FluidSynth threads, drained and emitted during =_process=; every signal reuses it. Then: playback callback → the granular channel + meta signals above, tick callback → =ticked=, status → =finished= / =looped=; migrate the =_process= watchdog onto =finished=; integration tests await signals instead of frame-counting.
4. *Channel voice completeness* — the full =midi-messages= controls on =AudioStreamFluidSynth= (bank/sfont/program select, key/channel pressure, sysex) plus the =get_*= queries.
5. *FX & settings surface* — the =AudioStreamFluidSynth= property groups above.
6. *FluidSynthSequencer* — the class and its live-input + scheduling surface.
7. *Voice callbacks* — the attach sweep and its two deferred signals.

The =godot-midi-player= addon (=project/addons/godot-midi-player=, fetched via =make addons=) rides along in the integration suites: it is the behavioral oracle for the signal contract, and =FluidSynthPlayer= is expected to be signal-compatible with it (both fed the same =project/assets/*.mid= fixtures).

Collateral: upstream memory-loader fix returns the custom loader and retires the tempfile workaround; pointer/dead-code sweep belongs to the cleanup issue on the forge.
