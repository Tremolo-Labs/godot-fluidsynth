* Godot FluidSynth
This plugin exposes [[https://www.fluidsynth.org/][FluidSynth]] to Godot 4 via [[https://docs.godotengine.org/en/stable/tutorials/scripting/gdextension/what_is_gdextension.html][GDExtension]] and the [[https://github.com/godotengine/godot-cpp][godot-cpp]] bindings. It exists for realtime MIDI playback inside the engine — complementing Godot's built-in MIDI input — by rendering SoundFont-driven synthesis directly into Godot's audio server.

** Usage
Build prerequisites and commands live in the [[file:README.md][README]] and in =SConstruct=. The example scene =project/main.tscn= drives the singleton from GDScript.

*** Playing a MIDI file
#+begin_src gdscript
extends Node2D
var fluidsynth: Node

func _ready() -> void:
	fluidsynth = Engine.get_singleton("FluidSynth")
	fluidsynth.call("play_midi")

# Direct voice control:
fluidsynth.call("program_select", 0, 0, 0)
fluidsynth.call("note_on", 0, 60, 127)
fluidsynth.call("pitch_bend", 0, 8192)
fluidsynth.call("note_off", 0, 60)
#+end_src

Imported assets are =MidiFileReader= (=.midstr=) and =SoundFontFileReader= (=.sf2str=) resources; paths resolve through =ResourceLoader= so exported games bundle them. Wiring in =project/main.gd:7= is late-bound via =call()= to avoid a hard GDScript dependency on the GDExtension.

** Design
FluidSynth assumes it owns file I/O and the audio driver. Godot owns both: assets are packed into =res://= and =.pck=, and the audio server pulls frames. The port bridges that gap with custom rendering, a custom SoundFont loader, and in-memory MIDI injection — three classes plus a GDScript importer.

- =FluidSynth= :: Singleton =Node= that owns =fluid_settings_t=, =fluid_synth_t= and a list of =fluid_player_t= handles, synthesizes into a float buffer, and is registered as =Engine singleton "FluidSynth"=.
- =AudioStreamFluidSynth= / =AudioStreamPlaybackFluidSynth= :: =AudioStream= pair that delegates =gen_tone= to the singleton, so the stream can be used in an =AudioStreamPlayer= (see =project/main.tscn:7=).
- =MidiFileReader= / =SoundFontFileReader= :: =Resource= wrappers holding raw =PackedByteArray= bytes so =.mid= / =.sf2= travel through Godot's resource system.
- =project/addons/midi/= :: =EditorImportPlugin= + =ResourceFormatLoader/Saver= converting =.mid→.midstr= and =.sf2→.sf2str= at import time.

*** Loading SoundFonts at runtime
The singleton's constructor registers a custom sfloader before any font is touched; the loader claims pseudo-paths beginning with =&= and decodes them back into memory pointers.

=SoundFontFileReader= implements the =fluid_sfloader_t= callbacks over its =PackedByteArray= (=src/soundfont_file_reader.cpp:82=); =sf_open= accepts only =&%p=, decodes the pointer, and returns it as the handle.

#+begin_src cpp :tangle src/soundfont_file_reader.cpp
void *SoundFontFileReader::sf_open(const char *filename) {
	void *p;
	if (filename[0] != '&')
		return NULL;
	sscanf(filename, "&%p", &p);
	Ref<SoundFontFileReader> *reader = reinterpret_cast<Ref<SoundFontFileReader> *>(const_cast<void *>(p));
	(*reader)->open();
	return p;
}
#+end_src

*** Handing MIDI data to the synthesizer
MIDI reaches the synth in-memory via =fluid_player_add_mem=. =FluidSynth::play_midi= (=src/fluidsynth_gdextension.cpp:99=) copies the =MidiFileReader= bytes into a stack buffer and feeds a fresh =fluid_player_t=:

#+begin_src cpp :tangle src/fluidsynth_gdextension.cpp
void FluidSynth::play_midi(Ref<MidiFileReader> p_midi_file) {
	Ref<MidiFileReader> local_midi_file;
	if (p_midi_file != NULL) {
		if (ResourceLoader::get_singleton()->exists(p_midi_file->get_path())) {
			Variant resource = ResourceLoader::get_singleton()->load(p_midi_file->get_path());
			local_midi_file = resource;
		}
	} else {
		local_midi_file = midi_file;
	}
	if (local_midi_file != NULL) {
		PackedByteArray byte_array = local_midi_file->get_data();
		if (byte_array.size() > 0) {
			fluid_player_t *fluid_player = new_fluid_player(synth);
			char midi_file[byte_array.size()];
			for (int i = 0; i < byte_array.size(); i++)
				midi_file[i] = byte_array[i];
			fluid_player_add_mem(fluid_player, midi_file, byte_array.size());
			fluid_player_play(fluid_player);
			fluid_players.append(fluid_player);
		}
	}
}
#+end_src

*** Rendering pipeline
=AudioStreamFluidSynth::gen_tone= delegates to the singleton, which renders interleaved stereo floats and fans them into Godot =AudioFrame=s:

#+begin_src cpp :tangle src/fluidsynth_gdextension.cpp
int FluidSynth::gen_tone(AudioFrame *p_buffer, float p_rate, int p_frames) {
	int64_t to_fill = p_frames;
	if (to_fill > 44100) to_fill = 44100;
	int result = fluid_synth_write_float(synth, to_fill, buffer, 0, 2, buffer, 1, 2);
	if (result == FLUID_FAILED) UtilityFunctions::print("failed to write to fluid_synth");
	int index = 0, p_index = 0;
	while (to_fill > 0) {
		p_buffer[p_index].left = buffer[index];
		p_buffer[p_index].right = buffer[index + 1];
		index += 2; p_index += 1; to_fill -= 1;
	}
	return p_frames;
}
#+end_src

=AudioStreamPlaybackFluidSynth::_mix= pulls whatever frames are available from the playback; =FluidSynth::process= (=src/fluidsynth_gdextension.cpp:142=) drains finished players each =NOTIFICATION_INTERNAL_PROCESS=:

#+begin_src cpp :tangle src/fluidsynth_gdextension.cpp
void FluidSynth::process(double delta) {
	Vector<fluid_player_t *> to_remove;
	for (int i = 0; i < fluid_players.size(); ++i)
		if (fluid_player_get_status(fluid_players[i]) == FLUID_PLAYER_DONE)
			to_remove.append(fluid_players[i]);
	for (int i = 0; i < to_remove.size(); ++i) {
		delete_fluid_player(to_remove[i]);
		fluid_players.erase(to_remove[i]);
	}
}
#+end_src

** Class architecture
Today =FluidSynth= is a monolith: one node owns the FluidSynth =settings=, =synth=, and =player= handles plus the audio pumping. FluidSynth itself draws cleaner seams — a synth you can strike immediately, a player that walks SMF tracks, and a sequencer that delivers events on a clock. Games want those seams too: driving a voice without loading a song, scheduling stabs on a timeline without a transport, tuning effects without touching playback.

The split keeps the singleton pattern: =FluidSynth= remains the voice/settings surface, and =FluidSynthPlayer= (=fluid_player_t= transport) and =FluidSynthSequencer= (=fluid_sequencer_t= timed events) become their own nodes.

The singleton also carries the voice and settings surface. Reverb and chorus are real DSP stages inside every =fluid_synth_write_float= pass — parameters arrive via settings keys, apply audibly on subsequent passes, and land in Godot *pre-bus* because our rendering pipeline pushes finished frames downstream. Godot buses remain the general effects rack; the synth-internal chain is tone shaping ahead of them.

- Channel voice :: =note_on/off=, =pitch_bend=, =cc=/=get_cc=, =bank_select=, =sfont_select=, =program_change=, =key_pressure=, =channel_pressure=
- Global :: =gain=, =polyphony=, =voice_count=, =all_notes_off(chan)=, =system_reset()=, =unload_font(id)=
- FX groups :: reverb (enabled/room-size/damping/width/level) and chorus (enabled/count/level/speed/depth) routed through =synth.reverb.*= / =synth.chorus.*= settings keys — never the deprecated direct setters; per-channel sends documented via cc 91/93
- Settings :: every runtime-relevant key becomes a property (dynamic sample loading, midi channels, cpu cores, period config); shell settings and LADSPA stay out — buses already bridge effects, and LADSPA is Linux-only
- Validation :: =fluid_is_soundfont= / =fluid_is_midifile= guards before loads

Voice callbacks ship deliberately, sharp edges documented: after each played or scheduled note-on, unregistered voices from =fluid_synth_get_voicelist= receive =fluid_voice_set_callback=; events flow through the deferred queue as =voice_note_off(id)= / =voice_finished(id)=. Class docs carry the header warnings verbatim: callbacks fire from the synthesis thread, block the DSP loop while running, must not call public API, and NOTEOFF never fires for one-shot percussion samples.

*** FluidSynthPlayer
Plays tracks: transport over Standard MIDI Files. Wraps =fluid_player_t= and replaces the =_process=-watchdog polling that currently recycles the player (and races replays into duplicated playlists) with an event-driven lifecycle.

Surface, drawn from the [[https://www.fluidsynth.org/wiki/api/midi_8h.html][player API]]:
- Transport :: =play=, =stop=, =seek(ticks)=, =set_loop(n)=
- Properties :: =tick= (=fluid_player_get_current_tick=), =total_ticks=, =bpm=, =division= (PPQ), =tempo= (=fluid_player_set_tempo=, including =FLUID_PLAYER_TEMPO_EXTERNAL=)
- Signals :: =finished= (from =FLUID_PLAYER_DONE=), =looped= (wrap detection via the tick callback), =ticked(tick)=

#+begin_src gdscript :tangle no
var p := FluidSynthPlayer.new()
p.midi_file = load("res://song.mid")
add_child(p)
p.set_loop(2)
p.play()
await p.finished
print("played %d ticks" % p.total_ticks)
#+end_src

The soundfont stays global: =FluidSynthPlayer= plays against whatever font the =FluidSynth= singleton has loaded.

*** FluidSynthSequencer
Timed event delivery to a synth — the future tense of =FluidSynth=. There is no overlap with the synth by construction: the synth executes commands *now*, the sequencer owns a clock and delivers them *later*. Boundary rule: any API taking a timestamp lives here, any immediate call lives there.

A dedicated class owns =fluid_sequencer_t=, registering the target player's synth as its client at construction (one sequencer per synth in v1). Events are built with the typed =fluid_event_*= constructors — notes, CC family (sustain/pan/volume/reverb send/modulation), program/bank selects, pitch bends, timers — and delivered at scheduled positions. All outbound command flow, so none of the DSP-thread hazards of the voice callbacks.

- Scheduling :: =schedule_note_on/off=, =schedule_cc=, =schedule_program_select=, =schedule_all_notes_off=, timer events
- Timeline :: sequencer-native milliseconds for v1; tick-domain helpers can layer later against =FluidSynthPlayer= 's =tick= property — mixing clocks early is where drift bugs live
- Housekeeping :: =cancel(from_ms)=, =clear()=

** Delivery plan
Signal plumbing must exist before anything event-shaped consumes it, so the phases order dependencies first; each lands as its own PR.

1. *Transport & performance surface* — =FluidSynthPlayer= properties/methods, validation guards; unit tests mirroring the existing suites.
2. *Deferred-emission infrastructure* — a lock-free queue fed from FluidSynth threads, drained and emitted during =_process=; every signal below reuses it. Then: playback callback → granular =midi_note_on/off= / =midi_control_change= / =midi_program_change= / =midi_pitch_bend=, tick callback → =ticked=, status → =finished= / =looped=; migrate the =_process= watchdog onto =finished=; integration tests await signals instead of frame-counting.
3. *Channel voice completeness* — bank/sfont/program selection, key and channel pressure.
4. *FX & settings surface* — the =FluidSynth= property groups above.
5. *FluidSynthSequencer* — the class and its scheduling surface.
6. *Voice callbacks* — the attach sweep and its two deferred signals.

Collateral: upstream memory-loader fix returns the custom loader and retires the tempfile workaround; pointer/dead-code sweep belongs to the cleanup issue on the forge.
